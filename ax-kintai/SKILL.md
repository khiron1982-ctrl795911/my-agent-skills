# A. アックス送付用3種の生成と突合検証

```

─────────────────                ─────────────────           ─────────────
5区分勤怠_1元データ                  在宅勤務者通勤費一覧 ─→ 通勤手当
  ↓ 超過残業算出シート(半休/時間休補正)   運転手当一覧(前月列) ─→ 運転手当      支給控除一覧SI④

  ↓ 先頭26列抽出         ├→ アックス送付 ─→ 遡及支払一覧(負) ──┐→ 欠勤控除減額    header=4）

```

### 1. 5区分勤怠データの生成ルール（自動）
- 元データは **`_3加算用`**（超過残業加算済み）。`_1元データ` は加算前なので使わない
  （202606では67名分の所定外・総残業が不一致になる）。
- 先頭26列（雇用区分コード〜代休付与日数）を**値と表示形式を保持して**抽出する。
  pandas の `to_excel` は timedelta を浮動小数点に変換して壊すため必ず openpyxl を使う。
- **遅刻者の残業足し戻し（自動適用）**: 遅刻時間>0 の社員は遅刻時間を残業に足し戻す。
  加算先は日別データ_半休時間計上用から自動判定する:
  - 期待法定外 = max(0, 退勤時刻 − (出勤予定時刻 + 8h + 休憩時間))
  - 法定外への加算 = clamp(期待法定外 − KOT日次所定時間外労働時間, 0, 遅刻時間)
  - 所定外への加算 = 残り。総残業時間(SI)には遅刻時間の全額を加算
  - 過去5ケース（2025/6田原→法定外、2025/10佐藤→所定外、2025/11宮崎→法定外、
    2026/1大城→法定外、2026/5伊藤→所定外）すべてで送付実績と一致を確認済み
  - **例外**: 休職・退職前後の社員は足し戻ししないことがある（例: 村石睦は遅刻2:23でも
    未適用）。config の `late_addback_exclude` に社員コードを列挙して除外する。
    適用結果はコンソールに必ず出るので、足し戻し対象者は担当者に一言確認するのが安全。

### 2. 60時間超過対象者の生成ルール（自動）
- 元データ: `譽田【…】60時間超過対象者(正社員&フレックス).xlsx` の「60時間越え算出シート」。
- 抽出条件: `合計`（=法定外労働時間+所定休日勤務時間）> 60:00。
- `60時間超 = 合計 - 60:00`。出力6列。202606で送付済と完全一致を確認済み。

### 3. フレックス勤務者勤怠データ（自動・202606の41名全員で完全一致確認済み）
- 元データから**雇用区分コード 1010/1060（フレックス系）のみ抽出**し、従業員コード昇順に並べる
  （正社員1000・SA2010等は除外。202606では3名除外）。
- レイアウト: 1〜4行=所定時間数設定ブロック（B2=営業日数が唯一の入力値）、5行目=35列ヘッダー。
- 列マッピング: A-F=元データ1-6列 / P-AI=元データ7-26列 / G-O=計算列:
  | 列 | 式 |
  |---|---|
  | G 休暇取得日数 | 有休 + 特休(有給) + 特休(無給) + 欠勤 + 代休取得 |
  | H 休暇取得時間 | G×7h + 有休時間休×1h |
  | I 所定(休暇合算) | F + H |
  | J 所定内不足時間 | 営業日数×7h − I（働き過ぎなら負） |
  | K 所定外(不足調整) | Q − J |
  | L 休業日数 | 空欄（必要時のみ手入力） |
  | M 総残業(確定) | P − J |
  | N 所定外(調整) | **min( M−(S+T), 営業日数h + max(0, −J) )** |
  | O 法定外(調整) | M − N − S − T |
- N式が肝: 基本枠=営業日数×1h（7h所定と8h法定の差×日数）。Jが負（余剰勤務）の分だけ
  枠が広がる。M−(S+T)が枠より小さければそのまま（O=0になる）。
- `eigyo_days`（勤怠対象月=前月の営業日数）は config 必須。営業日カレンダーで確認する。

### 4. 勤怠×支給控除一覧の突合（kintai_kyuyo_check.py）
- 支給控除一覧は header=4（5行目が見出し）、合計行は社員番号非数値で除外。
- 列対応: 所定外労働時間↔所定時間外.1 / 法定外↔普通残業時間 / 深夜↔深夜残業時間 /
  法定休日↔法定休日時間 / 所定休日↔所定休日時間 / 総残業(SI)↔時間外合計 /
  総出勤日数↔出勤日数 / 特休(有給+無給)↔特休日数 / 欠勤取得日数↔欠勤日数。
- **送付済の勤怠データを使えば全9項目が不一致0件になるのが正常**（202606で217名確認済み）。
  不一致が出たら元データの版（_1/_3）や手動加算漏れを疑う。

### 5. 変動データ×支給控除一覧の突合（check_hendo_vs_kyuyo.py）
検証済みマッピング（スクリプトに実装済み）:
1. 在宅勤務者通勤費一覧「通勤費」→「通勤手当」（一覧掲載者のみ比較）。
   「在宅勤務手当」は固定3,000円のマスタ管理項目で変動データ由来ではない。
2. 運転手当は**前月実績の後払い**: 運転手当一覧の前月列（6月給与なら5月列）と突合。
3. 遡及支払一覧の正の額→「遡及支払額」/ 負の額（誤支給回収等）→「欠勤控除減額」。
   負の額は欠勤控除一覧DBにも同額が記録されるため二重計上しない（DB優先で補完のみ）。
4. 会議スタッフデータの支払額計: 別給与がある既存従業員→「遡及支払額」、
   単発雇用者→「基本給」。判定は支給控除一覧の基本給と同額かどうか。
5. その他手当2一覧「給付」→「その他手当２」（弔慰金・出産祝い金等）。
6. 欠勤控除一覧(DB)の当月分（支給月列で絞り込み）欠勤控除額の絶対値→「欠勤控除減額」。

### 6. 既知の正当な例外（不一致に見えるが正しいもの）
- **退職者の個別精算**: 精算内訳書PDF（例: 202606 千葉幸作 欠勤控除137,222）は
  Excel変動データに載らず「片側のみ(給与側)」と出る。精算内訳書PDFを目視確認する。
- 社保の遡及徴収（例: 井上寛子の5月分）は「社保調整」列に反映される。
- 氏名は旧姓/改姓で変動データと支給控除一覧が異なることがある。突合キーは必ず社員番号。

### 7. 新しい月を処理する手順
1. `kintai_kyuyo_config.json` の `months` に対象月を追加（202606 をコピーしてパス・`eigyo_days` を修正）。
2. `py generate_ax_kintai.py --month YYYYMM --dry-run` で構造検証 → 本実行で3ファイルを output\ に生成。
3. コンソールの「足し戻し」レポートを確認（休職・退職者が含まれていたら
   `late_addback_exclude` に追加して再実行。全体を止めたい場合は `--no-late-addback`）。
4. 生成物を確認後、`アックス様送付資料` へコピーして送付。
   （過去月の再現検証をしたい場合は config の `verify_*` に送付済パスを書いて `--verify`）
5. 給与確定後: `py kintai_kyuyo_check.py --month YYYYMM` → 全項目不一致0を確認。
6. `py check_hendo_vs_kyuyo.py --month YYYYMM` → 不一致は§6の例外に該当するか確認。
   **§6で説明できない不一致が残る場合は、`cross-check` スキルで Codex に差分明細の
   セカンドオピニオンを取ってから報告する**（個人名・給与額はマスキングして渡す）。
7. 出力Excel（output\突合検証_*.xlsx / 変動突合_*.xlsx）を担当者に共有。

# B. 勤怠ローデータからの加工（一般アルバイト・振替休日など）

勤怠ローデータのパス（`勤怠データ\元データ`、日別データ等）を渡されて
「加工済み勤怠データを作って」と言われたときのルート。生成対象:

- `一般アルバイト勤怠データ.xlsx`（26列）← **Bルート専用（Aでは作らない）**
- 必要月のみ `振替休日データ一覧.xlsx` / `振替出勤データ一覧.xlsx`
  （ファイル名に「振替休日」「振替出勤」「振休者」「振出」を含むものをコピー）
- 5区分（26列）・フレックス（35列）・60時間超過（6列）も生成できるが、
  **アックス送付用にはAルートの生成物を使う**（§0参照）


## 生成後の確認（必須）

1. `attendance_processing_report.json` の warnings を必ず読む。
2. 列数チェック: 5区分・一般アルバイト=26列 / フレックス=35列 / 60時間超過=6列。
3. `従業員コード` に空欄がないこと。突合・照合のキーは必ず従業員コード（氏名は旧姓/改姓で揺れる）。
4. フレックスが26列元データから仮整形された場合は、休暇取得日数・所定内不足時間・

## Bルートの運用ルール

- 推測で不足データを作らない。ソースが見つからない出力は warning として報告する。
- 社員マスタ・退職者/休職者除外・手作業の値貼り付けや並び替えは、根拠がない限り確定ロジックに含めない。
- 5区分は `_3加算用` を優先ソースとし、先頭26列に絞る（末尾の補助数式列を壊れた参照のまま残さない）。

## 共通の注意

- 支給控除一覧の確定版は `確定データ\YYYYMM給与確定データSI\` 配下（計算結果④と同一）。
  月によって確定版の丸数字（④/⑤）が異なるので確定データフォルダ側を正とする。
- 送付用ファイル・原本を上書きしない: 生成物は `output\` や `加工済み勤怠データ\` に出し、
  確認後に手でコピーする。
- Excelを開いたまま実行すると PermissionError になる。
- 文字化けする場合は `$env:PYTHONIOENCODING="utf-8"; py -X utf8 ...`。
- 生成・突合スクリプト（generate_ax_kintai.py 等）のロジックを修正したときは、
  本実行の前に `cross-check` スキルで Codex のコードレビューを通す（給与に直結するため）。


## 完了判定

生成完了と給与確定を混同しない。対象月、各出力の件数、突合結果、未解決例外を明記し、
支給控除一覧との一致または人間による例外承認が確認できるまで「送付可」としない。
