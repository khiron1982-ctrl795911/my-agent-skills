# /code-review-skill — コード簡易チェックスキル

## 使い方
```
/code-review-skill                          # 直前に貼り付けたコードをチェック
/code-review-skill このマクロ動かない       # 症状を伝えてチェック
/code-review-skill script.py                # ファイルを指定してチェック
/code-review-skill --やさしく説明           # 専門用語なしで結果だけ知りたいとき
```

補足: プロジェクト全体の変更差分（git の変更点）をまとめて見てほしい場合は、Claude Code標準の `/code-review` コマンドの方が適しています。このスキルは「今送られてきた1つのコード」を素早く見るためのものです。

## このスキルがやること
1. 対象のコード（貼り付けテキストまたは指定ファイル）を読み込む
2. 明らかな間違い（動かなくなる原因）を探す
3. 無駄な処理や、同じことを繰り返している部分を探す
4. 変数名・処理の順番など、読みにくくて後で直しにくい部分を探す
5. 指摘ごとに「何が問題か」「なぜ問題か」「どう直すか」を平易な日本語でまとめる
6. 深刻度（すぐ直すべき／余裕があれば直す／お好みで）を振り分けて報告する

## 出力フォーマット
```
【コードチェック結果】

■ すぐ直した方がよい点
1. [場所: ○行目付近] 問題: （何が起きるか）
   理由: （なぜ問題か。専門用語には一言注釈）
   直し方: （具体的な修正案。コード例つき）

■ 余裕があれば直す点
1. [場所: ○行目付近] 問題: ／理由: ／直し方:

■ お好みで（見た目・書き方の整理）
1. ...

■ 総評
（全体として問題ないか、致命的な部分があるか、一言で）
```

## 検証チェックリスト
□ 指摘した箇所の行番号・場所が実際のコードと一致しているか
□ 専門用語（例外処理、null、非同期など）に平易な言い換えを添えているか
□ 「動かない」「エラーになる」レベルの問題を最優先で報告しているか
□ 憶測で指摘していないか（コードを実際に読んで確認したか）
□ 直し方の提案が具体的で、そのまま使えるコード例になっているか
□ プロジェクト全体差分のレビューではなく、渡された断片・ファイルの範囲に絞れているか

## 終了条件
チェック結果を報告したら終了。修正コードへの書き換えは、ユーザーから「直して」と明示的に指示されてから行う（無断でファイルを上書きしない）。

## フィードバック反映（自動ブラッシュアップ用）
- 実行前に `~/.claude/projects/C--Users-khiro/memory/feedback_skills.md` があれば読み、このスキルへの過去の修正指示を反映する
- ユーザーから出力への修正指示を受けたら、同ファイルに「日付／スキル名／指示内容／今後どうするか」を1行で追記し、同じ指摘を二度受けないようにする

## Codex連携（セカンドオピニオン）
- 結果に不安が残るとき、重要な判断を含むときは、/ask-codex でCodex（別のAI）にも同じ内容を見せて答え合わせができる
- Codexの指摘は鵜呑みにせず、Claude側で検証してから採用する（/ask-codex のルールに従う）
