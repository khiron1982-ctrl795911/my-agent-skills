# hr-recruiting — 採用・評価文書作成スキル

サイマル・インターナショナル人事総務課（桑田）の採用・評価業務向け。
公開ノウハウ（Uravation 30パターン / Claude Dojo 10業務 / HRMONY標準化）を
社内向けに再構成したもの。

## 鉄則（全メニュー共通・違反禁止）

1. **個人情報を入力に含めない・出力に残さない**
   - 削除必須: 氏名（イニシャル可）・住所・生年月日・連絡先・顔写真・ID番号
   - 変換必須: 経験年数は「約N年」、給与は概算、在籍期間は年単位
   - 許容: 職種・スキル・実績（概算数値）・個人特定されない粒度の行動事例
2. **生成物は必ず「下書き・叩き台」**。文末に「⚠️ 送信/提出前に担当者が内容・固有名詞・日付を確認」を付ける
3. **合否・評価の判断はしない**。情報整理と文章化のみ。判断は人間
4. **違法・不適切質問を含めない**: 家族構成・出身地・信仰・支持政党・健康情報（要配慮個人情報）
5. **評価文書に個人属性（年齢・性別・国籍）を混入させない**

## メニュー別手順

依頼内容を以下のどれかに分類し、不足入力があれば**最初に一度だけまとめて**質問する
（途中で何度も聞き返さない）。

### 1. 求人票・JD作成
- 入力: 職種 / 必須スキル / 歓迎スキル / 想定業務 / 雇用形態 / 勤務地・勤務形態
- 出力: ①ポジション概要（3行） ②業務内容（箇条書き5〜8個） ③必須要件 ④歓迎要件 ⑤働き方・環境
- トーン: 誠実・具体的。誇張表現（「アットホーム」等の空疎な語）を使わない

### 2. 面接質問リスト
- 入力: 職種 / 最重要能力1つ / 重視する価値観
- 出力（各質問に「確認したい能力」を1行付記）:
  - 過去経験を問う質問（STAR形式で深掘りできる形）: 6問
  - 問題解決力を測る質問: 4問
  - カルチャーフィット確認: 3問
  - 職種固有スキル確認: 5問

### 3. スカウトメール文面
- 入力: 媒体（ビズリーチ等） / ターゲットの職歴要約（匿名） / 訴求ポイント
- 出力: 件名2案 + 本文（候補者経験への言及→ポジション魅力→カジュアル面談提案の順、400字以内）
- 実際に返信が来た文面があれば `assets/scout-samples.md` に蓄積し、次回から参照する

### 4. お断りメール（不採用通知）
- 入力: 選考段階（書類/一次/最終） / ポジション名
- 出力: 感謝と敬意を軸にした簡潔な文面。不採用理由は書かない。傷つけない表現
- 本文が確定したら hr-mail スキルの手順で Gmail 下書き化まで行ってよい（送信はしない）

### 5. 評価コメント下書き（バイアス軽減版）
- 入力: 役割・主要業務（匿名） / 今期目標と達成状況 / 印象的な行動事実
- 出力条件:
  - 行動事実ベース（「〜だと思う」ではなく「〜した」）
  - 強みは「目標比較・行動比較・周囲への影響」の3視点
  - 成長余地は「さらに伸ばすと」の表現で書く
  - 300〜500字
- 出力後に自己チェック: 個人属性への言及が混入していないか1回読み直す

### 6. 1on1アジェンダ
- 入力: メンバーの役割 / 今期目標 / 前回からの継続事項 / 今回のテーマ
- 出力: 30分想定の時間割り当て付きアジェンダ + 各テーマの「確認したいこと」1〜2点 + 面談後記録フォーマット
- 末尾に固定注記:「このアジェンダは準備用。本番はメンバーの言葉を聴くことを最優先」

### 7. 退職面談サマリー
- 入力: 面談メモ（匿名化済みであることを確認してから受け取る）
- 出力: ①退職理由の分類（待遇/業務内容/人間関係/キャリア/その他） ②組織への改善ヒント3点 ③要フォロー事項

### 8. オンボーディング資料・研修資料
- 入力: 対象者の職種 / 入社日 / 既存資料の有無
- 出力: Week1 / Week2 / Week3-4 の段階別計画。既存資料があれば構成に組み込む
- カオナビ登録・社保手続きのチェックは new-employee-onboarding ルーティン（人事フォルダCLAUDE.md）を使う

## 出力先

  指定がなければ会話内出力のみ（個人情報を含む可能性があるファイルを勝手に作らない）

## 完了判定

候補者・従業員に関する推測、保護属性、評価根拠のない断定を残さない。用途、対象者、
事実根拠、送信・公開前の人間レビュー要否を添えて下書きとして提出する。

## 自己改善プロトコル（毎回実行）

スキル実行の最後に必ず確認する:
1. ユーザーから文面・手順への訂正があったか。手順どおりに進まなかった箇所はあるか
2. あれば、このSKILL.mdの該当箇所を直接修正するか、下の改善ログに1行追記する
   （形式: `- YYYY-MM-DD: [事象] → [変更内容]`）
3. 返信率が良かったスカウト文面・好評だった文書は assets/ に実例として保存する
4. 改善ログが10行を超えたら本文に統合してログを整理する

修正はClaude自身が行ってよい（承認不要）。手順の意味を変える大きな変更のみ一言報告する。
