# 経理仕訳検証スキル（keiri-shiwake-check）

## 目的

仕訳データを経理へ提出する前／freeeへ登録する前後に、機械的な検算で
転記ミス・行ズレ・月ズレ・重複を検出する。判断はせず「疑わしい行の列挙」まで。
最終判断は必ずユーザー（桑田さん）が行う。

## 出典・関連

- 検算ロジックの原型: hirotosuzuki/ClaudeCodeTraining の `accounting-consistency-check`
  スキル（公開スキル）を本環境向けに一般化したもの
- 給与×勤怠の突合は `ax-kintai` スキル（このスキルは会計仕訳側の検証）
- ※freee-mcp プラグインは 2026-07 に導入検討したが、freee アカウントがないため不採用

## 実行環境の約束

- スクリプト・中間ファイルは `C:\Users\kuwata\work\payroll-checks\` に作る
- 原本Excel・PDFは絶対に上書きしない（読み取り専用で開く）
- openpyxl 使用時は先頭で `sys.stdout.reconfigure(encoding='utf-8')`
- 元帳PDFがフォント埋め込みで文字化けする場合は pymupdf の
  `page.get_pixmap(dpi=300)` で画像化して読む（テキスト抽出しない）

## チェック項目（この順に実行）

### 1. 借貸一致チェック
- 仕訳1本ごとに 借方合計 = 貸方合計 を検算
- 不一致は 🔴（致命的）

### 2. 合計・内訳の検算
- 小計行・TTL行（例: 給与ファイル社会保険シートの29行目TTL、賞与ファイル32行目総計）と
  内訳セルの合計が一致するか再計算
- Excelの表示値でなく、内訳セルを自分で足し上げて比較する
- 不一致は 🔴

### 3. 勘定科目マスタ照合
- 使われている勘定科目コード・科目名が科目マスタに存在するか照合
- マスタの所在はユーザーに確認する（初回に確認したパスは本スキルの改善ログに追記して
  次回以降は自動で使う）。マスタ提供がない場合はこのチェックをスキップし、その旨を報告
- 未知の科目は 🟡（要レビュー）

### 4. 行ズレ・転記ミス検知（社保仕訳の要注意パターン）
- 健保・介護・厚年・雇用の各金額について「別の保険種別の行に同額が現れていないか」を
  総当たりで照合する（例: 厚年の金額が介護の行に入る行ズレ転記ミスの実績あり）
- 介護保険料が健保・厚年と同桁（数十万円）なら 🟡（介護は通常1桁小さい）

### 5. 月ズレ調整の突合
- 給与ファイルの月ズレ調整列（P-R列=健保/厚年/介護、U-W列=賞与月ズレ、
  AA-AC列=調整済み仕訳計上額）と、仕訳シートの計上額
  （L114=健保、L116=介護、L118=厚年、L120=雇用）が整合するか確認
- 元帳の月末消し込み（借方）が「翌月給与のTTL＋前月福利厚生分」と一致するか確認
- 不一致は 🔴、月ズレ調整額そのものの混入疑いは 🟡

### 6. 重複検知
- （日付, 勘定科目, 金額, 摘要）の同一タプルが複数回出現していないか
- 完全一致の重複は 🟡（意図的な同額仕訳もあるため致命的にはしない）

### 7. 預り金残高の連続性（元帳がある場合）
- 預り金科目（例: 60603 預り金社会保険料）について
  前月末残高 + 当月貸方（天引き） - 当月借方（納付・消し込み） = 当月末残高 を検算
- 不一致は 🔴。差額を必ず円単位で明示する

## 出力形式

1. サマリーテーブル: チェック項目 × 結果（OK / 🔴n件 / 🟡n件）
2. 問題行の明細: ファイル名・シート・セル番地・現在値・あるべき値（推定）・差額
3. 修正候補は「推定」と明記し、確度（%）を添える。勝手に修正しない
4. レポートは `work\payroll-checks\YYYYMM_shiwake_check.md` に保存

## 禁止事項

- 原本の修正・上書き
- 会計システムへの仕訳登録・更新・削除（このスキルは検証専用）
- 差額の原因を断定して報告すること（必ず「確度」を付けて仮説として報告）
