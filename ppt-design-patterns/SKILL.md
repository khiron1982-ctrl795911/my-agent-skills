# PPT — パワーポイント デザインパターン適用スキル

## スキルの目的
伝えたい情報の構造に合わせて、最適なパワーポイントデザインパターンを選定・提案する。
出典: パワーポイントのデザインパターン大全

## 役割分担（他スキルとの関係）
- このスキルは**「どう見せるか」を決めるまで**が担当（パターン選定・レイアウト提案）
- パターン決定後の**実装・修正・視覚QA**は `pptx-simul` を読む
  （フォントサイズ規則・SIMUL固有のカラー/サイズ設定・COMレンダリングQAはそちらに集約）
- 入力メモから章立て・各スライドの主張を作る場合は `powerpoint-corrections` を先に読む

---

## 実行手順

### Step 1: 情報の構造を診断する

ユーザーが提示したコンテンツを見て、以下の2軸で分類する。

**軸1: 要素間に関係があるか？**
- **ある** → カテゴリA（関係図系）
- **ない** → カテゴリB（羅列・グラフ系）
- **ページ種別で決まる** → カテゴリC（表紙・定型系）

**軸2: 何を伝えたいか？**
- 並べて見せたい → 並列
- 違いを見せたい → 比較
- 順序・手順を見せたい → フロー
- 繰り返す仕組みを見せたい → サイクル
- 上下の階層を見せたい → ピラミッド
- 位置関係・重複・包含を見せたい → その他関係図
- 数字の変化・割合を見せたい → グラフ
- 画面キャプチャを使いたい → キャプチャ
- 価格・表・場所・スケジュールを整理したい → その他定型

---

### Step 2: パターンを選定する

#### カテゴリA: 要素間の関係がある（関係図系）

**並列**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 1 | 横並び | テキスト量が少ない。2〜3要素を左右に並べる |
| 2 | 縦並び | テキスト量が多い。1カラムで上下に積む |
| 3 | 複数羅列 | 4つ以上の要素を格子状に配置 |

**比較**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 4 | 規模比較 | 市場規模・数字の大小を視覚化（面積・棒の長さ） |
| 5 | 項目比較 | 対応領域やフローの違いを左右で比べる |
| 6 | 表での比較 | 複数項目・複数軸を一度に比較 |

**フロー**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 7 | 横型フロー | 情報量が少ない。ステップが3〜5個 |
| 8 | 縦型フロー | 項目が多く横に収まらない場合 |
| 9 | 箱型フロー | 条件分岐・分岐後の合流がある場合 |

**サイクル**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 10 | 円型サイクル | 要素が少ない（3〜4個）循環プロセス |
| 11 | 四角型サイクル | 要素が多い循環プロセス |

**ピラミッド**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 12 | ピラミッド型 | 上位ほど規模が小さくなる階層（例: 経営層→現場） |
| 13 | じょうろ型 | 下位ほど規模が小さくなる（例: 入力→絞り込み→出力） |

**その他関係図**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 14 | マトリクス | 2軸で4象限に分類（ポジショニングマップ等） |
| 15 | ベン図 | 複数要素の重複・共通部分を表現 |
| 16 | ツリー図 | 親子関係・構成要素の全体像 |
| 17 | 数式 | 算出方法・定義式を示す |
| 18 | 掛け算 | 要素の相乗効果（A × B = C） |
| 19 | 足し算 | 要素の組み合わせ（A + B = C） |
| 20 | 領域 | 自社が対応する範囲をビジュアルで示す |
| 21 | 階段 | プロセスの段階的なステップアップ |
| 22 | 重複 | 情報が一部重なることを表現 |
| 23 | 包括 | 大きな概念の中に小さな概念が含まれる |
| 24 | 相互関係 | 双方向の関係性 |
| 25 | ビフォーアフター | 従来との違い・改善効果の前後比較 |

#### カテゴリB: 要素間の関係がない（羅列・グラフ系）

**グラフ**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 26 | 縦棒グラフ | 数値の伸び率・増減（時系列） |
| 27 | 横棒グラフ | 項目間の大小比較（ランキング的） |
| 28 | 円グラフ | 全体に占める割合 |
| 29 | 折れ線グラフ | 数値の推移・トレンド |
| 30 | その他グラフ | 積み上げ棒・複合グラフ等 |

**キャプチャ**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 31 | 羅列 | 複数画面を並べて見せる |
| 32 | 拡大 | 特定部分を拡大して説明 |
| 33 | フロー | 画面遷移の流れを示す |

**その他定型**
| # | パターン名 | 使いどき |
|---|-----------|---------|
| 34 | 料金体系（表） | 項目が多いプラン比較 |
| 35 | 料金体系（その他） | 項目が少ないシンプルな価格表示 |
| 36 | 表 | テキスト量が多い情報の整理 |
| 37 | 拠点 | 事業所の位置関係（地図活用） |
| 38 | スケジュール | 導入・プロジェクトの流れ（ガントチャート等） |
| 39 | ランキング | 順位形式のデータ |
| 40 | 事例 | 導入事例・ケーススタディの紹介 |
| 41 | テキストのみ | 補足説明・注意書き等の補助ページ |
| 42 | Q&A | よくある質問と回答 |
| 43 | 名言・メッセージ | 代表メッセージ・引用 |
| 44 | ピクトグラム | アイコン中心の視覚的表現 |

#### カテゴリC: ページ種別で決まる定型

| # | パターン名 | 使いどき |
|---|-----------|---------|
| 45 | 表紙（テキスト少） | 資料名のみ。シンプルなビジュアル重視 |
| 46 | 表紙（テキスト多） | 日付・会社名・担当者等の追加情報あり |

### Step 3: 提案フォーマット

```
【診断結果】
伝えたい内容: ○○
情報の構造: ○○（関係あり/なし/定型）

【推奨パターン】
第1候補: [パターン名] — 理由
第2候補: [パターン名] — 理由（代替案）

【レイアウトのヒント】
- ...

【注意点】
- ...
```

パターン確定後、実装に進む場合は `pptx-simul` のルール（フォント18pt以上・
はみ出し4辺チェック・COMレンダリングQA等）に従って作業する。

## 早引き: 状況別パターン選択チートシート

| 状況 | 推奨パターン |
|------|------------|
| 3つの特徴を並べたい | 横並び（テキスト少）/ 縦並び（テキスト多） |
| AとBを比べたい | 項目比較 / 表での比較 |
| 手順を説明したい | 横型フロー（短い）/ 縦型フロー（長い） |
| PDCAなど繰り返しを示したい | 円型サイクル |
| 組織階層を示したい | ツリー図 / ピラミッド型 |
| 2軸で分類したい | マトリクス |
| 重なりを示したい | ベン図 |
| 時系列の数値推移 | 折れ線グラフ |
| 割合を見せたい | 円グラフ |
| 項目の大小を比べたい | 横棒グラフ |
| ビフォーアフターを見せたい | ビフォーアフター |
| 価格プランを整理したい | 料金体系（表）/（その他） |
| 導入スケジュールを示したい | スケジュール |
| 画面の使い方を説明したい | キャプチャ（羅列/拡大/フロー） |


## 自己改善プロトコル（毎回実行）

このスキルは Sonnet 5 での実行を前提に手順を明示している。
判断に迷ったら本文の規則のみに従い、推測で進めず不明点はユーザーに質問する。

スキル実行の最後に必ず確認する:
1. ユーザーからの訂正・追加指示があったか。手順どおりに進まなかった箇所
   （パス変更・ファイル形式変更・コマンドエラー等）はあるか
2. あれば、このSKILL.mdの該当箇所を直接修正するか、下の改善ログに1行追記する
   （形式: `- YYYY-MM-DD: [事象] → [変更内容]`）
3. 改善ログが10行を超えたら本文に統合してログを整理する

修正はClaude自身が行ってよい（承認不要）。手順の意味を変える大きな変更のみ一言報告する。
