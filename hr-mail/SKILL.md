# 人事メール下書き 半自動化スキル

## 絶対ルール（安全ゲート）

1. **送信は絶対にしない。** Gmail連携では `create_draft`（下書き作成）のみ使用。
   送信操作を求められても「下書きまで。送信はGmail画面からご自身で」と案内する。
2. 下書き作成前に、**本文全文と宛先をチャットで提示してユーザーの承認を得る。**
3. 宛先メールアドレスが不明・曖昧なら推測せず確認する（誤送信リスクの根絶）。
4. 給与額・評価・健康情報など機微情報は、ユーザーが明示的に指示しない限り本文に入れない。
5. 候補者・派遣会社など**社外宛は特に慎重に**: 社名・敬称・署名を必ず確認する。

## 手順

1. 用途を判定し、`templates.md` から該当テンプレートを選ぶ
   （該当なしなら型を流用して新規作成し、templates.md への追加を提案する）
2. 不足情報（宛先名・日付・事実関係）を確認する。**推測で埋めた箇所は【要確認】マークを付けて示す**
3. 本文を組み立ててチャットに提示 → ユーザー承認
4. 承認後、Gmail連携が使えれば下書きを作成し、「Gmailの下書きフォルダに入れました」と報告する。
   使えなければコピペ用に整形して終了
5. 同種メールを繰り返し作った場合は、テンプレート化して `templates.md` に追記することを提案する

## 文体ルール

- 社内宛: 「お疲れ様です。人事の桑田です。」から始める簡潔なですます調。要件→依頼→期限の順
- 社外宛（候補者・派遣会社・取引先）: 「お世話になっております。株式会社サイマル・インターナショナル 人事の桑田です。」
  から始める丁寧語。クッション言葉を適度に
- 文章をさらに丁寧にしたいときは `e-mail` スキル（丁寧な日本語化）を併用できる
- 件名は「【依頼】」「【確認】」「【リマインド】」「【日程調整】」等のプレフィックスを付ける

## 勤怠チェック連携（kintai-check スキルから呼ばれる場合)

`確認サマリー_YYYYMM.md` の人別リストを入力として:

- 🔴打刻漏れ → 本人宛「勤怠打刻の修正依頼」（テンプレA1）。対象日付を列挙する
- 🔴残業45h超 → 上長宛「残業時間超過の共有」（テンプレA2）
- 🟡備考あり要確認 → 本人宛の個別確認（備考内容を引用して質問形式に）
- 同一人物に複数指摘がある場合は1通にまとめる
- 宛先アドレスは自動では引かない。**名前だけ入れた下書きにし、宛先はユーザーが設定する**
  （またはユーザーからアドレス一覧をもらった場合のみ設定）

## 完了判定

宛先、敬称、依頼期限、添付・リンク、個人情報の露出を最終確認する。送信・予約送信・
既読管理は実行せず、作成した下書きまたは本文案と未確定事項を明示して渡す。

## 自己改善プロトコル（毎回実行）

このスキルは Sonnet 5 での実行を前提に手順を明示している。
判断に迷ったら本文の規則のみに従い、推測で進めず不明点はユーザーに質問する。

スキル実行の最後に必ず確認する:
1. ユーザーからの訂正・追加指示があったか。手順どおりに進まなかった箇所
   （パス変更・ファイル形式変更・コマンドエラー等）はあるか
2. あれば、このSKILL.mdの該当箇所を直接修正するか、下の改善ログに1行追記する
   （形式: `- YYYY-MM-DD: [事象] → [変更内容]`）
3. 改善ログが10行を超えたら本文に統合してログを整理する

修正はClaude自身が行ってよい（承認不要）。手順の意味を変える大きな変更のみ一言報告する。
