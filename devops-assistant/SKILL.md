# /devops-assistant — 変更管理・反映作業サポートスキル

## 使い方
```
/devops-assistant 今の変更を保存したい          # git commit（変更の記録）を案内
/devops-assistant 前の状態に戻したい            # 取り消し方法を確認してから実施
/devops-assistant これを本番に反映したい        # デプロイ手順を確認してから実施
/devops-assistant 今の状態を教えて              # git status など現状確認のみ
```

## このスキルがやること
1. 今の状態を確認する（変更されたファイル、保存済みか未保存か）
2. やりたいこと（保存・共有・元に戻す・反映）を平易な言葉で確認する
3. 必要なコマンドを提示し、「これは何をするものか」を一言添える
4. 破壊的な操作（元に戻せない・上書きされる操作）に該当するかを判定する
5. 破壊的な操作、公開・反映系の操作（デプロイ等）は、実行前に必ずユーザーの承認を取る
6. 承認が得られたら実行し、結果を報告する

## 破壊的操作リスト（実行前に必ず一言確認すること）
以下に当てはまる操作は、内容を説明したうえで「実行してよいですか？」と確認してから実行する。無断では絶対に実行しない。

```
□ force push（強制的にサーバー側の履歴を上書きする操作）
□ reset --hard（保存していない変更を消して、指定した時点に巻き戻す操作）
□ clean -f（保存していない新規ファイルを削除する操作）
□ branch -D（作業の枝＝ブランチを強制的に削除する操作）
□ 本番環境へのデプロイ（実際に公開・反映する操作）
□ 履歴の書き換え（rebase、amendなど、過去の記録を変える操作）
```

## 出力フォーマット
```
【現状確認】
- 変更されたファイル: ...
- 保存（コミット）済みか: ...

【提案するコマンド】
1. コマンド: `git ...`
   これは何をするものか: （一言で）
   破壊的操作か: はい／いいえ
   （「はい」の場合）→ 実行前に必ず確認します。よろしいですか？

【実行結果】
（承認後に実行し、結果を報告）
```

## 検証チェックリスト
□ 破壊的操作リストに該当する場合、実行前に承認を取ったか
□ 各コマンドに「何をするものか」の一言説明を添えたか
□ APIキーやパスワードをコマンドやファイルにそのまま書いていないか（.envのみに置く）
□ デプロイ（本番反映）は承認なしに実行していないか
□ ファイルの削除・上書き・移動を行う前に対象を確認したか
□ 実行結果（成功・失敗）をユーザーに分かる言葉で報告したか

## 終了条件
提案したコマンドの実行が完了し、結果を報告したら終了。破壊的操作や反映系の操作で承認が得られない場合は、実行せずに待機する。
