# /sns-insight — SNSインサイト分析・改善提案スキル

## 使い方
```
/sns-insight                      # Threads直近10投稿を分析
/sns-insight --limit 20           # 直近20投稿を分析
/sns-insight --file data.json     # 保存済みJSONを分析
/sns-insight --weekly             # 週次サマリーと改善提案
/sns-insight --next               # 次の投稿テーマを3つ提案
```

## このスキルがやること

### データ取得→分析モード
1. `python ~/sns/scripts/threads_insights.py --save` を実行してデータ取得
2. 取得した `_drafts/insights/*.json` を読み込む
3. 以下の軸で分析する：
   - 閲覧数TOP3の共通点（フック・テーマ・長さ）
   - エンゲージメント率（いいね÷閲覧）が高い投稿の特徴
   - 最適投稿時間帯（タイムスタンプから推定）
   - テーマ別パフォーマンス比較
   - PR投稿（下書きファイル名に `_PR` が付くもの。ルールは `~/sns/AFFILIATE.md`）の反応を通常投稿と比較。PR投稿だけ極端に反応が落ちていれば頻度・書き方の見直しを提案する

### 分析レポートフォーマット
```
【Threads インサイト分析レポート】YYYY-MM-DD

■ サマリー
- 分析期間: {期間}
- 総閲覧数: {N}
- 平均エンゲージメント率: {N}%

■ 伸びた投稿の特徴
1. {特徴1}
2. {特徴2}

■ 改善ポイント
- {改善点1}
- {改善点2}

■ 次回推奨テーマ（3案）
1. {テーマ1} — 理由: {理由}
2. {テーマ2} — 理由: {理由}
3. {テーマ3} — 理由: {理由}
```

### フィードバック蓄積
分析から得た知見を `~/.claude/projects/C--Users-khiro/memory/feedback_sns.md` に追記する。
「伸びる投稿の法則」として蓄積し、次の生成に活かす。

## /loop との組み合わせ方
```
# 週次サイクル
/loop 今週のThreadsインサイトを/sns-insightで分析して改善提案を_drafts/insights/に保存したら止まって

# 連続サイクル（分析→次の投稿生成まで）
/loop インサイトを分析して→伸びたテーマで今日のThreads下書き3本生成→_drafts/に保存されたら止まって
```

## 検証チェックリスト
□ 数値（閲覧数・エンゲージメント率）を実データから計算したか（憶測で書いていないか）
□ 「伸びた投稿の特徴」に根拠となる投稿を紐づけているか
□ 次回推奨テーマ3案それぞれに理由を添えたか
□ 得られた知見を feedback_sns.md に追記したか

## 終了条件
分析レポートと改善提案が `~/sns/_drafts/insights/YYYY-MM-DD_report.md` に保存されたら止まる。

## APIなしでも使える（手動分析モード）
Threads APIが未設定の場合は、投稿URLや数値を貼り付けると手動分析を実行する。
例: 「先週の投稿データです: 投稿1: 閲覧1200/いいね45...」
