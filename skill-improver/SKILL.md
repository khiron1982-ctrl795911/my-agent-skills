# Skill Improver — 自己改善ループ

## 仕組みの全体像

スキルは自動では書き換わらない。よって改善は次の**3ステップループ**で回す：

```
① 記録（毎回）: スキル使用後、問題点をその場で言語化
② 反映（その場 or 週次）: SKILL.md の改訂版を生成
③ 配置（HIROの操作）: 改訂版を再アップロード / ~/.claude/skills に上書き
```

**Claude Code（ローカル）で使う場合**は ③ をClaudeが直接実行できるため、
ループが完全に閉じる。claude.ai（Web）の場合は改訂版zipを出力し再アップロードを案内する。

## ① 記録 — 使用後レトロ（1分で終わる形式）

スキル使用タスクの完了時、以下の3問だけ確認する：

1. **エラー・手戻りはあったか？**（あれば具体的に何か）
2. **ユーザーが手で直した箇所はあるか？**（＝スキルの指示が不足していた証拠）
3. **次回も再現したい工夫はあったか？**

1つでもYesがあれば、対象スキルのSKILL.md末尾 `<!-- CHANGELOG -->` の直前に
`## 改善候補ログ` として日付付きで追記した改訂版を提案する。

## ② 反映 — 改訂の原則

- **症状ではなく原因を書く**：「エラーが出たら再実行」ではなく「エラーの原因となる前提条件をチェックするコードを冒頭に置く」
- **1回の失敗で断定しない**：2回発生したら本文ルール化、1回なら改善候補ログ止まり
- **descriptionのトリガー改善**：スキルが起動しなかった事例があれば、その時のユーザー発言をdescriptionのキーワードに追加する（発動漏れは最頻の劣化要因）
- **500行ルール**：SKILL.mdが500行を超えたら詳細を `references/` に分離
- **バージョン付記**：CHANGELOGに `日付 vX.Y: 変更内容` を必ず1行追記

## ③ 配置 — 環境別手順

| 環境 | 手順 |
|---|---|
| claude.ai (Web) | 改訂版フォルダをzip化して出力 → 設定 > 機能 > スキル で差し替え |
| Claude Code | `~/.claude/skills/{skill名}/SKILL.md` を直接上書き（Claudeが実行可能） |
| 併用時 | Claude Code側を正とし、Webへは週次でzip同期 |

## 週次レビュー（推奨：金曜）

「スキルの週次レビューをして」と言われたら：
1. 各スキルの改善候補ログを集約
2. 2回以上発生した問題を本文ルールに昇格した改訂版を全スキル分生成
3. `codex-bridge` を使い、コード含有スキル（hr-dashboard / video系）はCodexにも
   レビューを依頼するHANDOFF.mdを同時生成
4. 改訂サマリー表（スキル名 / 変更点 / 影響度）を提示

## 品質測定（月次・任意）

skill-creator の検証手順を使い、代表プロンプト3〜5本で各スキルの発動率と
成果物品質を確認する。詳細は `C:\\Users\\kuwata\\.codex\\skills\\.system\\skill-creator\\SKILL.md` を参照。

## 禁止事項

- ユーザー確認なしにスキルの目的・スコープ自体を変えない（微修正のみ自律可）
- 個人情報・認証情報をSKILL.mdに書き込まない（パスは環境変数化を提案）
- 改善ログを理由にSKILL.mdを無限に肥大化させない（四半期ごとに棚卸し）
