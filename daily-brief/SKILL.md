# /daily-brief — 朝のブリーフィングスキル

## 使い方
```
/daily-brief            # 今日のブリーフィングを生成
/daily-brief --sns      # SNS関連だけ
```

## このスキルがやること

### Step 1: 情報を集める（読むだけ。何も変更しない）
1. **SNS下書き**: `~/sns/_drafts/threads/`・`instagram/`・`x/` を走査し、「[下書き - 要確認]」を含む未確認ファイルを数える（ファイル名と先頭30文字も控える）
2. **前日の成果物**:
   - `C:\Users\khiro\OneDrive\Desktop\VIDEO\` 配下で直近24時間に更新されたフォルダ（＝昨日作った動画）
   - `~/sns/_drafts/insights/` の最新レポート日付
3. **今日・今後のタスク**:
   - `~/.claude/projects/C--Users-khiro/memory/MEMORY.md` と各 project_*.md の「残タスク」「手作業待ち」項目
   - `~/.claude/scheduled-tasks/` にある定期タスクの一覧（今日動く予定のもの）
4. **フィードバック未反映**: `memory/feedback_skills.md`・`feedback_sns.md` に「反映済み」印のない項目があるか

### Step 2: 1枚にまとめて出力する
```
【今日のブリーフィング】YYYY-MM-DD（曜日）

■ 承認待ち（あなたの確認が必要なもの）
- SNS未確認下書き: {N}件（Threads {n} / Instagram {n} / X {n}）
  → 確認するには: /sns-draft
- その他の承認待ち: {あれば}

■ 昨日の成果
- 動画: {フォルダ名 or なし}
- SNS: {生成・分析があれば}

■ 今日の予定（自動で動くもの）
- {定期タスク名}: {時刻}

■ 手作業待ち・残タスク（メモリより）
- {例: OpenAI/GeminiのAPIキー再発行}

■ ひとこと提案
{今日やると良さそうなこと1つ。なければ「特になし」}
```

### Step 3: 保存
- 同じ内容を `~/.claude/skills/daily-brief/logs/YYYY-MM-DD.md` に保存する（7日より古いログは削除してよい）

## 検証チェックリスト
□ ファイルの読み取りだけで、下書きや設定を一切変更していないか
□ 件数は実際にファイルを数えた結果か（憶測でないか）
□ 承認待ちを一番上に置いたか（ユーザーが最初に見るべき情報）
□ 5分で読める長さに収まっているか（詰め込みすぎない）

## フィードバック反映（自動ブラッシュアップ用）
- 実行前に `~/.claude/projects/C--Users-khiro/memory/feedback_skills.md` があれば読み、このスキルへの過去の修正指示を反映する
- ユーザーから出力への修正指示を受けたら、同ファイルに「日付／スキル名／指示内容／今後どうするか」を1行で追記し、同じ指摘を二度受けないようにする

## 終了条件
ブリーフィングを画面に出力し、ログを保存したら止まる。下書きの承認・タスクの実行はユーザーの指示を待つ。
