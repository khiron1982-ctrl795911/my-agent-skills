# PowerPoint Design Pattern Reference

This reference summarizes the Cone/c-slide "39 design patterns" source for selecting layouts in Japanese business PowerPoint decks. Use it as a decision table, not as fixed visual templates.

## Core Page Model

- Title: short slide topic.
- Lead message: the slide's main message, ideally within 1-2 lines.
- Object area: visual explanation, evidence, reasons, examples, diagrams, charts, or screenshots.

Design difficulty usually concentrates in the object area. Choose the pattern by the relationship among objects and by the fixed nature of the page type.

## Three-Way Decision

| Category | Use when |
|---|---|
| Related elements | Elements have a relationship such as parallel, comparison, flow, hierarchy, overlap, inclusion, formula, or before/after. |
| No specific relationship | The content type already implies the layout, such as graph, screenshot, pricing, table, location, schedule, ranking, case study, Q&A, quote, or icon-based explanation. |
| Page-type fixed | The page role already implies the layout, such as cover, agenda, company overview, member profile, MVV, history, traction, or org chart. |

## 1. Related Elements

| Pattern | Use when | Layout guidance |
|---|---|---|
| Horizontal parallel | Few elements and short text. | Place 2-3 items horizontally; icons or simple boxes work well. |
| Vertical parallel | Each element has more text. | Stack items vertically so descriptions stay around 2-3 lines. |
| Multiple listing | Four or more parallel items. | Prioritize hierarchy; enlarge the key item, number, or explanation. |
| Scale comparison | Market size, percentages, or size difference matters. | Use shape size or chart-like emphasis to show magnitude. |
| Item comparison | Different scopes, stages, or capabilities are compared. | Use color, boundary lines, or dashed areas to show differences. |
| Table comparison | Many comparison criteria must be read at once. | Use a table; emphasize winners or important cells. |
| Horizontal flow | Few steps or low text volume. | Show steps left to right; icons help when text is light. |
| Vertical flow | Too many steps for horizontal layout. | Stack steps top to bottom; suitable for onboarding or usage flow. |
| Box flow | Branches, many steps, or multiple lanes exist. | Use boxes; vertical axis can show category and horizontal axis can show time. |
| Circular cycle | Few recurring elements. | Use circular arrows and label what each arrow means. |
| Rectangular cycle | Many recurring elements. | Use a rectangular loop to preserve room for labels. |
| Pyramid | Higher levels are smaller or more selective. | Watch for text overflow at the top; add contrast or glow if needed. |
| Funnel | Lower levels become smaller or more selective. | Use for narrowing processes or selection stages. |
| Matrix | Positioning on two axes or four quadrants. | Label axes clearly and keep plotted items sparse. |
| Venn diagram | Overlap between elements matters. | Use 20-30% transparency so intersections remain visible. |
| Tree | Whole-part or branching structure must be shown. | Keep hierarchy levels aligned and avoid tiny labels. |
| Formula | A number, concept, or definition is calculated. | Prefer symbolic formulas over long prose explanations. |
| Multiplication | Synergy or combined effect is multiplicative. | Use x-shaped operators or grouped objects to show contribution. |
| Addition | Combination of elements creates the result. | Use plus operators or grouped items. |
| Area | Supported range, coverage, or target area must be shown. | Highlight only the relevant region. |
| Staircase | Staged progress or maturity levels. | Use ascending steps with concise stage labels. |
| Duplication | Information overlaps and should not be repeated. | Consolidate common text once and show shared vs unique portions. |
| Inclusion | One element belongs inside another. | Use nested circles or boxes. |
| Mutual relationship | Two parties exchange value or influence. | Label arrows with what is provided and what is received. |
| Before/after | Conventional state and changed state must be contrasted. | Use an arrow from before to after; make the difference explicit. |

## 2. No Specific Relationship

| Pattern | Use when | Layout guidance |
|---|---|---|
| Vertical bar graph | Growth rate, increase/decrease, or component growth matters. | Emphasize the most important bar or delta. |
| Horizontal bar graph | Survey answers or category ranking by size. | Sort values and keep labels readable. |
| Pie chart | Share or composition ratio matters. | Move key labels outside the pie when emphasis is needed. |
| Line chart | Time-series transition matters. | Annotate the key change point or trend. |
| Other graph | Combination, stacked, or mixed chart is needed. | Use only when it adds interpretation beyond a simple chart. |
| Screenshot listing | Multiple screenshots are shown simply. | Align screenshot edges and crop consistently. |
| Screenshot enlargement | A UI area or transition must be explained. | Pair whole screenshot with enlarged detail and callout. |
| Screenshot flow | Screen transitions matter. | Connect screenshots with arrows and step labels. |
| Pricing table | Many pricing conditions or plan differences exist. | Use a table and highlight the recommended or target plan. |
| Pricing freeform | Few pricing items exist. | Make numbers large and units small. |
| Generic table | Text amount is high or icons are unnecessary. | Use row/column hierarchy and reduce grid noise. |
| Location/base | Office or business location relationship matters. | Use maps, pins, or regional grouping. |
| Schedule | Timeline to implementation or delivery must be shown. | Use flow or table depending on granularity. |
| Ranking | Position, rank, or ordered data matters. | Use chart or table; make rank numbers prominent. |
| Case study | Customer or implementation example is introduced. | Combine capture/image, key result, and explanatory text. |
| Text only | Supplemental prose must be shown. | Add contrast in size/weight between the key phrase and explanation. |
| Q&A | FAQ or webinar-style question handling. | Pair Q and A clearly; keep each answer compact. |
| Quote/message | Authority quote or executive message needs impact. | Use photo or capture with a prominent short message. |
| Pictogram | Spoken explanation would otherwise look plain. | Add icons to reinforce concepts without clutter. |

## 3. Page-Type Fixed

| Pattern | Use when | Layout guidance |
|---|---|---|
| Cover, little text | Only deck title or minimal metadata exists. | Use simple title-first composition. |
| Cover, much text | Title plus date, company, subtitle, or notes exist. | Distribute metadata to corners to keep the title clean. |
| Agenda, normal | Few agenda items. | Keep numbering and spacing consistent. |
| Agenda with headings | Many agenda items. | Group items under section headings. |
| Dot agenda | More heading levels or many items. | Use compact dot-based hierarchy. |
| Circular agenda | Oral presentation or webinar needs visual orientation. | Use circular structure for visibility and memorability. |
| Company overview, normal | Logo and standard profile items are available. | Use logo plus core company information. |
| Company overview, text only | No logo or many profile fields. | Remove logo area and prioritize fields. |
| Company overview, photo background | Recruiting pitch or brand feel matters. | Use a still image with protected text contrast. |
| Company overview with clients | Client logos strengthen credibility. | Place representative logos within the overview page. |
| Company overview, other | Multiple extra information types are needed. | Use divided sections with strict hierarchy. |
| Member profile, 1 person | Founder or representative profile. | Use large photo/name and concise credentials. |
| Member profile, 2 people | Executive pair or cofounders. | Balance two columns evenly. |
| Member profile, 3 people | Three key members. | Use equal cards or columns. |
| Member profile, 4+ people | Team list. | Add repeated boxes and reduce detail per person. |
| MVV with photo background | Vision/mission needs emotional impact. | Use large statement over strong but legible imagery. |
| MVV text only | Values have substantial text. | Use clean text hierarchy and enough spacing. |
| MVV other | Service, product, or character visuals should be shown. | Combine visuals with concise principle statements. |
| Photo background, centered text | Tagline is short and central. | Large tagline, smaller explanation. |
| Photo background, left text | Tagline or explanation is longer. | Align text left and use overlay if needed. |
| Photo background, two photos | Multiple messages or scenes exist. | Split the imagery while maintaining one lead message. |
| Photo background, webinar | Presentation needs rhythm or chapter break. | Use as a pacing slide, not an information-dense slide. |
| Photo background, other | Many elements must sit on a photo. | Adjust object transparency and contrast for legibility. |
| Company history, timeline | Milestones or events matter. | Use chronological sequence. |
| Company history, graph | Organization or revenue growth matters. | Use graph-forward layout. |
| Company history, combined | Timeline plus graph or brand image are both needed. | Combine timeline and visual evidence without crowding. |
| Traction, logos only | Client name value is the proof. | Use clean logo grid. |
| Traction, numbers | Results or effect should be proven. | Make specific numbers prominent. |
| Traction, laurel/ranking | Authority or award status matters. | Use ranking/award motif carefully and cite basis. |
| Org chart | Organization structure must be explained. | Use hierarchy boxes and clear reporting lines. |

## Audit Checklist

- Does each slide have one clear message?
- Does the chosen pattern match the information relationship?
- Is the most important text or number visibly dominant?
- Are long descriptions avoiding narrow columns and excessive line breaks?
- Are chart labels, units, and source notes readable?
- Are screenshots cropped and annotated enough to explain the point?
- Are tables scannable, with emphasis on important cells?
- Is any photo-background text protected by sufficient contrast?
- Is any duplicated text consolidated?
- Are source claims, rankings, and customer logos backed by evidence?
